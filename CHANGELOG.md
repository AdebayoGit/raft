## [0.1.0] — Unreleased

The first cut of Raft. Storage engine, document layer, queries, transactions, and live observers across all four platform bindings.

### Added

#### Core (`raft-db`)
- LSM-tree storage engine — WAL with HLC timestamps and crc32 checksums, in-memory MemTable, immutable SSTables with bloom filters and block index, level-aware compaction.
- Document layer (`Database`) on top of the engine: per-collection in-memory state, version tracking, JSON-encoded persistence under `__doc__/{coll}/{id}` keys.
- Typed predicate query engine: `Filter` (Eq / Lt / Gt / Lte / Gte / Contains / And / Or), `Sort`, `Limit`, `Offset`. No SQL parser — typed only.
- Optimistic-concurrency transactions: `DbTransaction::get/put/delete/commit/rollback` with conflict detection on commit.
- Reactive layer: `EventBus` broadcasting `MutationEvent`s; `LiveQuery` re-evaluates a query on each mutation and emits `QueryDiff` (`added` / `removed` / `updated`).
- CRDT primitives: LWW register, OR-Set, counter. Schema-declared per field for deterministic conflict resolution.
- C ABI surface (`core/include/raft.h`, generated by cbindgen):
  - Lifecycle: `rft_open`, `rft_close`.
  - Raw KV: `rft_put`, `rft_get`, `rft_delete`.
  - Collections: `rft_collection_put / put_auto / get / delete / count / list_ids`.
  - Queries: `rft_query_execute / result_count / result_get / result_free`.
  - Transactions: `rft_transaction_begin / get / put / delete / commit / rollback`.
  - Observers: `rft_observe`, `rft_observe_query`, `rft_unobserve`. Both deliver C callbacks with JSON-encoded events; `rft_observe_query` fires an initial-snapshot diff synchronously before the first event.
- 9 typed error codes covering null pointers, UTF-8 validation, I/O failures, missing keys, buffer sizing, JSON parse, transaction conflicts, invalid handles, and unknown subscriptions.

#### Platform bindings
- **Flutter (`raft_db`)** — `RaftDb.open` + put / get / delete / close on `Uint8List`, two-phase reads (size query → exact buffer). `RaftCollection<T>` with function-based serialize/deserialize and key prefixing under `<name>:<id>`. `RaftDbException.fromCode` covering all 9 error codes.
- **Android (`com.raftdb`)** — `RaftDb` with suspend functions and `Flow`-based observer stubs. `RaftCollection<T>` with serialize/deserialize functions. `RaftError` sealed class with all 9 typed subclasses. JNI shim in `cpp-adapter.cpp` and `raft-jni.cpp` translating `Java_com_raft_HybridRaft_native*` symbols to `rft_*`.
- **Swift (`RaftDB`)** — `async`/`await` API with `RaftCollection<T: Codable>` (custom encoders supported), `AsyncStream` observer stubs, `RaftError` enum with all 9 cases.
- **React Native (`react-native-raft`)** — Nitro-based hybrid object exposing open / put / get / delete / close / watch / unwatch with Promise APIs. Watch fires the callback with a current snapshot and on every matching write.

#### Documentation
- Root `README.md` with architecture diagram and install matrix.
- Platform quickstarts for Flutter, Android, Swift, and React Native.
- `VERSIONING.md` documenting the cross-platform semver policy.

### Fixed
- iOS empty-value bug: `nativeGet` was returning `nil` for present-but-empty values, conflating them with "not found". Now returns an empty string to match Kotlin.
- Race in live-query bootstrap: `Database::live_query` now subscribes to the event bus *before* taking the initial snapshot, so any mutation in that window is buffered on the receiver and surfaces as the first diff.
- Kotlin observer iteration: `notifyObservers` now snapshots the observer map before invoking callbacks, so a callback that re-enters `watch`/`unwatch` doesn't mutate the live `ConcurrentHashMap` mid-iteration.

### Changed
- The `ffi` Cargo feature now implies `async` (the observer FFI requires a tokio runtime) and pulls in `serde_json` for JSON envelopes at the boundary.
- `RaftDbException._fromCode` (Flutter) is now public `RaftDbException.fromCode`, matching the Kotlin and Swift naming.

### Test coverage
- Rust core: 360 unit / integration tests pass on `--features ffi`.
- Flutter: 20 unit tests + 10+ integration tests.
- Kotlin: 28 unit tests covering RaftError mapping, QueryResult equality, and RaftCollection scoping.
- Swift: 35 unit tests covering RaftError, QueryDiff, LockedBool concurrency, and RaftCollection scoping.
- React Native: 26 Jest tests covering open / put / get / delete / close / watch plus edge cases (UTF-8 keys, prefix overlap, 50-way concurrent put, post-close throws).
